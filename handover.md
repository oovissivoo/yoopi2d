# Продолжение работы: Yoopi2D на Mac M1

## Цель пользователя

Собрать и запустить форк Pencil2D **Yoopi2D** на **Apple M1, macOS Sequoia 15.5**. Продолжать работу до реального запуска и проверки основных функций. Пользователь общается по-русски и предпочитает простые инструкции и самостоятельное выполнение доступных действий.

## Текущее состояние

Работа продолжена на Apple M1, macOS Sequoia 15.5. Qt 5.15.19 и FFmpeg/ffprobe 9.0.2 установлены через Homebrew. Приложение скомпилировано для arm64, Qt/Cocoa упакованы, локальная подпись прошла проверку, `--version` завершился успешно, GUI открылось.

Тестовый рисунок пользователя закрыт через «Quit» без сохранения. Старые пакеты из `dist` удалены. Последняя проверенная сборка Nurture2D находится в `yoopi2d/output/Nurture2D-M1/dist/Nurture2D.app` и запущена. При последней проверке исправлено масштабирование иконок верхней панели: значки теперь отрисовываются Qt в DPR-aware буфере и окрашиваются поверх альфа-маски. В свежем окне значки помещаются в свои ячейки и выровнены по центру. Исходники теперь настроены на сборку под новым именем Yoopi2D; после переименования новую сборку ещё не создавали.

Во время сборки выявлены и исправлены проблемы скрипта: `tee`-редирект лога не работал в среде запуска; аргументы `lipo` стояли в неверном порядке; `macdeployqt` не скопировал `libbrotlicommon.1.dylib` и `libsharpyuv.0.dylib`, нужные Qt Cocoa plugin. Исправления внесены в `build-macos.command`. Рабочая реализация верхней панели находится в `CUI/cosmiccontrolcenter.cpp` (именно её компилирует qmake). Последняя GUI-правка устранила ручное масштабирование иконок; полный прогон успешно завершён, приложение визуально проверено. Журнал: `yoopi2d/output/Nurture2D-M1/logs/build-20261021-200830.log`.

Клавиша F7 добавила кадр (индикатор сменился с 0:01 на 0:02); панель Cell Bank видна и открывается. Созданы тестовые GIF и MP4 через установленный FFmpeg, затем ffprobe подтвердил формат и длительность. Это проверяет сам FFmpeg, но не экспорт/импорт из приложения. Рисование проверено пользователем на тестовом рисунке; затем рисунок закрыт без сохранения по его просьбе.

После первой правки в одноимённом файле `app/src` выяснилось, что он не компилируется в этом проекте; поэтому сборки с ней визуально не менялись. Исправление внесено в подключённый `CUI/cosmiccontrolcenter.cpp`; после сборки проверено на открытом окне. Затем остаются проверки воспроизведения, сохранения/повторного открытия `.pclx`, импорта аудио, экспорта из приложения и планшета. FFmpeg отдельно создавал и проверял GIF/MP4, но это не подтверждает экспорт из приложения. Подробный протокол в `yoopi2d/output/Nurture2D-M1/VALIDATION-RU.txt`.

## Начать на Mac

В новом чате прочитать этот файл, найти распакованный проект и проверить фактическое состояние среды. Не считать Homebrew, Command Line Tools или Qt уже установленными.

Команда сборки:

```bash
/bin/bash "$HOME/Downloads/Nurture2D-M1/build-macos.command"
```

Скрипт:

- Проверяет macOS 15+ и ARM64; при запуске через Rosetta пытается перезапуститься нативно.
- Проверяет наличие компилятора. Если Command Line Tools отсутствуют, открывает установку и просит повторить запуск после её завершения.
- При отсутствии устанавливает Homebrew официальным установщиком; затем выполняет `brew install qt@5 ffmpeg`.
- Ожидает ARM Homebrew в `/opt/homebrew` и Qt 5 из `brew --prefix qt@5`.
- Собирает генератор кистей отдельным проектом qmake, создаёт четыре PNG, затем собирает приложение.
- Явно задаёт `QMAKE_APPLE_DEVICE_ARCHS=arm64`, `QMAKE_MACOSX_DEPLOYMENT_TARGET=15.0`, release, `NO_TESTS`, `PENCIL2D_RELEASE`, `VERSION=2026.0.0`.
- Ограничивает параллельную компиляцию четырьмя задачами.
- Упаковывает Qt через `macdeployqt`, проверяет Cocoa plugin, plist и ARM64, выполняет локальную ad-hoc подпись и её проверку.
- Запускает приложение с `--version`, проверяет FFmpeg и ffprobe, копирует результат в `dist/Nurture2D.app` и открывает его.

Для сборки без автоматического открытия окон результата:

```bash
YOOPI2D_NO_OPEN=1 /bin/bash "$HOME/Downloads/Nurture2D-M1/build-macos.command"
```

Этот параметр отключает только финальные команды `open`; проверка `--version` всё равно использует обычный macOS интерфейс Qt.

Скрипт сохраняет журналы в `logs/build-YYYYMMDD-HHMMSS.log`, а результаты компиляции — в уникальных папках `build-macos-arm64.XXXXXX`. Старые сборки сохраняются. Новое приложение создаётся в `dist/Yoopi2D.app`; предыдущая проверенная сборка `dist/Nurture2D.app` остаётся отдельным старым вариантом.

## Внесённые изменения

Пути ниже указаны относительно папки проекта на Mac:

| Файл | Изменение |
| --- | --- |
| `build-macos.command` | Новый сценарий установки зависимостей, сборки, упаковки, проверки и запуска на Apple Silicon. |
| `app/app.pro` | Старый генератор кистей с Linux-подобными `-lQt5Core -lQt5Gui` помещён в `!macx` scope. На Mac генератор собирается скриптом через собственный `.pro`. |
| `tools/generate_brush_tips/generate_brush_tips.pro` | Добавлен `CONFIG += c++11`. |
| `util/common.pri` | `-Wl,-s` ограничен `unix:!macx`; удалена зависимость от Carbon, оставлены objc/AppKit. |
| `core_lib/src/external/macosx/macosx.cpp` | Удалены CoreFoundation include и недокументированный `SetMouseCoalescingEnabled`; используются уже существующие обёртки `MacOSXNative::setMouseCoalescingEnabled`. Прежний выбор значения `gIsMouseCoalescing` сохранён. |
| `core_lib/src/external/macosx/macosxnative.mm` | Исправлено `Appkit.h` → `AppKit.h` для файловых систем с учётом регистра. |
| `app/data/Info.plist` | `CFBundlePackageType` исправлен с `BNDL` на `APPL`; `NSHighResolutionCapable` стал `<true/>`. |
| `core_lib/src/util/util.cpp` | На macOS FFmpeg/ffprobe ищутся сначала рядом с приложением в `plugins`, затем в `/opt/homebrew/bin` и `/usr/local/bin`, чтобы запуск из Finder не зависел от PATH терминала. |
| `START-HERE-RU.md`, `VALIDATION-RU.txt` | Инструкции и точный список выполненных/невыполненных проверок. |

Приложение собирается проектом `pencil2d.pro`, который последовательно собирает `core_lib` и `app`; тесты исключаются через `CONFIG+=NO_TESTS`. В `app/app.pro` задан `TARGET = yoopi2d`, а macOS bundle называется `Yoopi2D`. Скрипт находит созданный `.app` и читает имя executable из его plist.

## Выполненные проверки в Windows

- SHA-256 оригинального архива совпал с digest GitHub release asset.
- Скрипт разобран как Bash утилитой shfmt 3.14.1; окончания строк LF.
- В комплекте найдены все 305 файлов ресурсов, перечисленные в `app.qrc` и `core_lib.qrc`.
- Проверено наличие 594 явно перечисленных файлов проектов qmake.
- Plist разобран как XML, проверены `APPL` и boolean Retina.
- Проверено наличие изменённых файлов внутри итогового ZIP и совпадение упакованного скрипта с подготовленным.
- Итоговый ZIP содержит 2433 файла, размер 20 728 626 байт.

Эти проверки **не заменяют** компиляцию C++/Objective-C++ с macOS SDK, проверку линковки и запуск на M1.

## Что проверить и довести до конца

1. Запустить сборку. При ошибке прочитать первый содержательный compiler/linker error в журнале, исправить причину в подготовленных исходниках и повторить нужный этап. Не ограничиваться пересказом ошибки пользователю.
2. Проверить, что настоящий executable имеет архитектуру ARM64, Qt frameworks и Cocoa plugin упакованы, подпись проходит проверку и приложение запускается из Finder.
3. Проверить рисование, создание кадров и воспроизведение анимации.
4. Сохранить тестовый `.pclx`, закрыть и снова открыть его.
5. Проверить импорт аудио и экспорт короткого видео/GIF через установленный FFmpeg.
6. При наличии планшета проверить нажим пера и горячие клавиши. Без планшета не заявлять, что нажим проверен.
7. При успешном результате обновить документацию: версия macOS/Qt, внесённые дополнительные правки, реально выполненные проверки и расположение готового приложения.

Особые места для проверки: пригодность Homebrew Qt 5 на фактической системе, сборка старого macOS backend современным SDK, `macdeployqt` и ad-hoc подпись. Это пока потенциальные точки отказа, а не подтверждённые ошибки.

FFmpeg в этом сценарии остаётся зависимостью Homebrew. Qt упаковывается в `.app`. **Переносимость `.app` на другой чистый Mac не подтверждена**; текущая цель — рабочий запуск на Mac пользователя. Для самостоятельного дистрибутива понадобится отдельно упаковать FFmpeg с зависимостями и проверить его на другом Mac. Apple Developer certificate и notarization не подготовлены. Защиту macOS целиком отключать не нужно.
