Проверено на Apple M1, macOS Sequoia 15.5, 21 октября 2026.

Готовая версия:
- `dist/Nurture2D.app` — последняя сборка, запущена для GUI-проверки. Старый пакет удалён.
- Исходный executable имеет архитектуру arm64.
- `codesign --verify --deep --strict` для dist-приложения завершился успешно.
- Qt 5.15.19 упакован, Cocoa plugin `libqcocoa.dylib` присутствует.
- Запуск `nurture2d --version` завершился с кодом 0.
- Приложение открылось в графическом режиме и показало рабочее окно Nurture2D.
- FFmpeg/ffprobe 9.0.2 работают. Созданы тестовые односекундные GIF и MP4 с аудиодорожкой; ffprobe распознал оба файла и их длительность.
- В интерфейсе добавлен кадр клавишей F7: индикатор изменился с 0:01 на 0:02. Панель Cell Bank открывается и доступна через элементы управления доступностью.

Исправления, сделанные при сборке:
- Для этого окружения перенаправление журнала через `tee` заменено обычной записью в файл.
- Исправлен порядок аргументов `lipo -verify_arch arm64`.
- Добавлено копирование `libbrotlicommon.1.dylib` и `libsharpyuv.0.dylib`: Qt Cocoa plugin ссылался на них, а macdeployqt их не добавлял.
- В подключённом `CUI/cosmiccontrolcenter.cpp` исправлено масштабирование иконок: Qt рисует их в буфер с учётом DPR, затем применяется цветовая маска.
- Полный повторный прогон `build-macos.command` после исправления интерфейса успешно завершён; arm64, упаковка Qt и подпись проверены. Свежий GUI визуально проверен: иконки помещаются в ячейки верхней панели и выровнены по центру.

Что пока не подтверждено:
- Рисование мышью/пером, сохранение и повторное открытие `.pclx`, импорт аудио и экспорт из самого приложения.
- Управляющий ввод мышью в основное окно сейчас блокируется ошибкой компьютерного управления `noWindowsAvailable`; поэтому это ограничение среды проверки, а не установленная ошибка приложения. Ввод с клавиатуры и снимки экрана работают.
- Воспроизведение анимации, планшет и нажим пера.
- Переносимость `.app` на другой Mac. FFmpeg остаётся установленным через Homebrew.
- Сборка запускалась с `NURTURE2D_NO_OPEN=1`; приложение затем запущено вручную для визуальной проверки. Тестовый рисунок пользователя закрыт без сохранения по его просьбе.

Журналы сборки находятся в `logs/`. Первый запуск скрипта остановился на отсутствующих зависимостях Cocoa plugin; последующая сборка успешно скомпилировала приложение, после чего недостающие библиотеки добавили и подпись/запуск проверили.
